**Date:** October 24, 2025  
**Focus:** Understanding the difference between functions that return values and those that produce side effects.

## Topics Covered
- Functions that **cause side effects** (e.g., modifying variables, logging output)  
- Functions that **return values** for later use  
- **Pure vs. Impure functions** and why purity improves code reliability  
- Balancing side effects and return values for cleaner program design

### Exercise 2: Pure vs. Impure Functions  
Created two versions of an addition function to observe the difference between **pure** and **impure** behavior.  
The pure version always produced the same result for the same input, while the impure one depended on an external variable.  
**Concepts:** Function purity, predictability, dependency management.  
File: `pureAndImpure.js`  

---

## Code Summary
Today’s study emphasized that not all functions are meant to return values, some exist to perform necessary side effects.  
However, **pure functions** are ideal when you want reliability and testability, as they depend only on their inputs and not on external state.  
The key is knowing when to use side effects and how to limit them for cleaner, more predictable programs.
